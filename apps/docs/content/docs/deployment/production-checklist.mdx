title: Production Checklist
description: A practical launch checklist for a Convoy deployment.
---

Use this checklist before opening the system to real users.

## Convex Backend

- [ ] Production deployment created in [Convex dashboard](https://dashboard.convex.dev)
- [ ] Environment variables set in Convex dashboard (Settings → Environment Variables):
  - `CLERK_JWT_ISSUER_DOMAIN` (required; a placeholder such as `https://convex.invalid` in Convex Auth mode)
  - `AUTH_MODE=convex` (Convex Auth mode)
  - `AUTH_EMAIL_VERIFICATION` (Convex Auth mode; unset means `required`)
  - Optionally `AUTH_GOOGLE_CLIENT_ID` and `AUTH_GOOGLE_CLIENT_SECRET`, for Google sign-in
  - `RESEND_API_KEY` (if using email; required in Convex Auth mode while verification is required)
  - `EMAIL_FROM` (if using email), on a domain verified in Resend
  - `SUPPORT_EMAIL` (if using email; without it emails name no help address)
  - `NEXT_PUBLIC_APP_URL` with its scheme (required in Convex Auth mode; otherwise if email links should target a non-default app host)
- [ ] Functions and schema deployed (`npx convex deploy`)
- [ ] Components tab shows no "unmounted" entries
- [ ] Tables visible in Data tab

## Web App

- [ ] Deployed to hosting provider (Vercel, etc.)
- [ ] `NEXT_PUBLIC_AUTH_MODE` set to the mode you chose (unset means `convex`)
- [ ] `NEXT_PUBLIC_CONVEX_URL` points to the production Convex deployment (or injected via integrated build)

## Authentication

Convex Auth mode:

- [ ] `NEXT_PUBLIC_APP_URL` set on the web host, matching the Convex deployment
- [ ] With verification required, a sign-up from an address outside your Resend account gets the email, and its link signs in
- [ ] With Google configured, the client lists `<Convex site URL>/auth/google/callback` and "Continue with Google" signs in

Clerk mode:

- [ ] Production Clerk application created
- [ ] Production Clerk keys configured (`NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY`)
- [ ] Clerk sign-in/sign-up URLs configured
- [ ] JWT template configured for Convex in Clerk dashboard
- [ ] `CLERK_JWT_ISSUER_DOMAIN` in Convex matches the production Clerk issuer

## Product Smoke Tests

- [ ] Sign in works
- [ ] Organization and project pages load
- [ ] Tasks can be created and updated
- [ ] Attachments upload correctly
- [ ] Thread pages render

## CLI and Integration Checks

- [ ] API key generation works
- [ ] `convoy setup` works against production
- [ ] `convoy connect` can register and stay connected
- [ ] MCP config generated by `convoy init mcp` is valid

## Operational Readiness

- [ ] Logs are reachable (Convex dashboard → Logs)
- [ ] Rollback approach is understood
- [ ] At least one admin can diagnose auth and deployment issues
