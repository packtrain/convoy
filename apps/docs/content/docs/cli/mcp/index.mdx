---
title: Connect an MCP client
description: Expose Convoy tasks and project context to MCP-aware AI clients.
---

Convoy ships an MCP (Model Context Protocol) server, so AI clients like
Claude Code, Codex, OpenCode, and Antigravity can read and write your tasks directly from the
editor — project-scoped task lookup and search, comments, artifacts, and
task creation/updates. The full catalog is in the
[`MCP tools reference`](/docs/reference/mcp-tools).

MCP works independently of live thread execution. You do not need the
Convoy CLI or a saved profile to connect directly. Use your deployment's
MCP endpoint and authenticate through OAuth or a user API key.

## Connect with OAuth (Claude Code)

The fastest path for clients with OAuth support — no API key handling at all:

```bash
claude mcp add --transport http convoy \
  "https://<DEPLOYMENT>.convex.site/api/mcp?project=<ORG_SLUG>/<PROJECT_ALIAS>"
```

Then run `/mcp` in Claude Code and follow the browser flow: sign in to
Convoy, click **Approve**, done. The client receives its own API key
automatically (visible under your account's API keys as
`MCP (Claude Code)`); when it expires, `/mcp` re-authenticates with one
click.

For clients configured with a bearer token, use the header-based examples
below. Create a user [API key](/docs/cli/api-keys) and copy the
project-scoped endpoint from Convoy's **Configure MCP** dialog.

## Prerequisites

For direct configuration, you need the deployment URL, project scope, and
an account with permission to access that project. OAuth handles sign-in
in the browser; manual header configuration needs an API key.

Only the optional CLI config generator below needs a saved profile. Use
[Install and connect](/docs/cli) to set one up. Generated config embeds the
profile's API key, so keep those files out of version control.

## Generate the config

From the repository or workspace you want the client to operate on:

```bash
convoy init mcp                # choose clients interactively
convoy init mcp --cli claude   # writes .mcp.json
convoy init mcp --cli codex    # writes .codex/config.toml
convoy init mcp --cli opencode # writes opencode.json
convoy init mcp --cli antigravity # writes ~/.gemini/config/mcp_config.json
```

Antigravity has no project-scope MCP file, so `--cli antigravity` writes
your user config and ignores `--output-dir`. Every agy session then uses
the project you ran `init` in. For that reason `convoy init mcp` without
`--cli` leaves Antigravity out.

Useful flags:

- `--output-dir <path>` — write config somewhere other than the current
  directory
- `--force` — overwrite existing config without prompting (otherwise
  Convoy asks first)

## Verify

1. Restart the client so it picks up the new config.
2. Open the repo that now contains the config.
3. Ask the client to list or search tasks — a working setup returns
   project-scoped results.

If nothing shows up, check that the generated config file exists at the
expected path, the profile points at the correct project, and the API key
is valid. See [`MCP troubleshooting`](/docs/cli/mcp/troubleshooting) for
the longer symptom list.

## Manual OpenCode configuration

To configure OpenCode by hand instead of using `init`, add the server to
`opencode.json` in the project folder (replace the URL with your
deployment's and the token with your API key):

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "convoy": {
      "type": "remote",
      "url": "https://your-deployment.convex.site/api/mcp?project=acme/WEB",
      "headers": { "Authorization": "Bearer sk_user_..." },
      "oauth": false
    }
  }
}
```

`opencode.json` contains your API key — add it to `.gitignore`.

## Manual Antigravity configuration

To configure Antigravity by hand, run `agy mcp add` with your deployment's
URL and your API key. Quote the URL: `?` is a glob character in zsh.

```bash
agy mcp add --header "Authorization: Bearer <YOUR_API_KEY>" convoy \
  "https://<DEPLOYMENT>.convex.site/api/mcp?project=<ORG_SLUG>/<PROJECT_ALIAS>"
```

`agy mcp list` shows the server afterwards.

## Manual Codex configuration

To configure Codex by hand instead of using `init`, create
`.codex/config.toml` in the project folder. Replace the URL with your
Convex backend URL and project scope, and the bearer token with an API key
from Convoy user settings:

```toml
[mcp_servers.convoy]
url = "https://<DEPLOYMENT>.convex.site/api/mcp?project=<ORG_SLUG>/<PROJECT_ALIAS>"

[mcp_servers.convoy.http_headers]
Authorization = "Bearer <YOUR_API_KEY>"
```

The API key popup in Convoy fills in the backend URL at runtime; opened
from a project route, it also scopes the URL with
`?project=<ORG>/<ALIAS>`.

You can also open the project header gear menu and choose **Configure MCP**
to copy project-scoped `.mcp.json`, `.codex/config.toml`, `opencode.json` and
`agy mcp add` snippets for the current project.

## Project vs. user scope

Think about config scope before writing files:

- use **project scope** when the config should travel with the repo —
  preferred for shared team repos
- use **user scope** when the config is machine-specific

Generated config embeds your API key. Before committing project-scoped
config, verify the file is ignored by version control or strip the key —
see the [`Security model`](/docs/cli/security).
